# TASK-GUIDE — Понятное руководство по созданию магазина

Это инструкция для человека, который пока не умеет программировать. Представляй сайт как магазин в торговом центре: есть витрина, полки, карточки товаров, корзина, касса и склад. Мы будем создавать эти части по очереди.

## Перед началом: что понадобится
- Компьютер и интернет.
- VS Code ode.js — — программа, в которой открывают и редактируют файлы проекта.
- Nпрограмма, которая позволяет запускать инструменты для создания сайта.
- Аккаунт GitHub — место, где можно хранить историю проекта.
- Аккаунт Neon — онлайн-база данных.
- Google Cloud project — нужен для входа через Google.
- Доступ к настройкам YooMoney — нужен только на этапе тестовой оплаты.

**Важно:** не отправляй никому пароли и секретные ключи. Не вставляй их в исходный код сайта и не публикуй файл `.env.local`.

## Шаг 1. Создай основу сайта
**Что делаем:** создаём пустой проект Next.js с TypeScript.

**Простыми словами:** это как получить пустое помещение магазина, в котором уже есть электричество и стены, но ещё нет полок и товаров.

**Что попросить у помощника по коду:**  
«Создай Next.js-проект с TypeScript и Tailwind CSS. Объясни каждую команду простыми словами. После каждого этапа напиши, как проверить, что всё получилось».

**Как понять, что готово:** сайт открывается на компьютере по локальному адресу, который показывает терминал, обычно `http://localhost:3000`.

## Шаг 2. Настрой внешний вид
**Что делаем:** создаём шапку, меню, фон, кнопки, карточки и сетку товаров.

**Простыми словами:** сначала строим витрину и расставляем полки, но пока без настоящих товаров.

**Правила дизайна:**
- Светлый фон, белые карточки, тёмный читаемый текст.
- Основной акцент — один спокойный цвет, например фиолетовый.
- На главной можно использовать Bento Grid: одна крупная карточка новинки и несколько компактных рядом.
- В обычном каталоге карточки должны быть понятными и аккуратно выровненными.
- Качественные фото техники важнее декоративных эффектов.
- Не добавляй много градиентов, случайных цветов и анимаций.

**Как понять, что готово:** главная страница выглядит как магазин, меню работает, а на телефоне ничего не вылезает за край экрана.

## Шаг 3. Подключи Neon — место, где хранятся товары
**Что делаем:** создаём базу данных Neon и соединяем её с сайтом.

**Простыми словами:** Neon — это складская книга. В ней будут записаны названия товаров, цены, фотографии, характеристики и остатки.

1. Создай проект в Neon.
2. Скопируй строку подключения к базе данных.
3. В проекте создай файл `.env.local`.
4. Добавь строку подключения в переменную `DATABASE_URL`.
5. Проверь, что `.env.local` исключён из Git и не попадает в публичный репозиторий.
6. Создай таблицы и запусти миграции.

**Важно:** строка подключения — секрет. Не вставляй её в сообщение, которое будет опубликовано, и не помещай в код, который запускается в браузере.

**Как понять, что готово:** сайт может получить список тестовых товаров из базы.

## Шаг 4. Добавь тестовые товары
**Что делаем:** заполняем магазин несколькими выдуманными товарами, чтобы проверить функции.

**Простыми словами:** прежде чем открывать магазин, нужно расставить товары на полки. Пока можно использовать демонстрационные данные.

Для каждого товара подготовь название, бренд, цену в сумах, количество на складе, фото, описание и характеристики. Не используй чужие фотографии без разрешения. Не выдавай тестовые цены и остатки за реальные.

**Как понять, что готово:** товары отображаются на главной и в каталоге, а данные берутся из базы.

## Шаг 5. Сделай каталог удобным
**Что делаем:** добавляем поиск, фильтры и сортировку.

- **Поиск** находит товар по названию или бренду.
- **Фильтр** оставляет, например, только ноутбуки или товары выбранного бренда.
- **Сортировка** меняет порядок: дешевле сначала, дороже сначала или сначала новинки.
- **Пагинация** показывает товары порциями, а не огромным списком сразу.

**Как понять, что готово:** при выборе фильтра список действительно меняется, а не просто подсвечивается кнопка.

## Шаг 6. Сделай отдельную страницу для каждого товара
**Что делаем:** создаём страницу с большим фото, названием, ценой, характеристиками, наличием и кнопками.

**Простыми словами:** у каждого товара будет свой адрес, как отдельная страница в каталоге. Например, адрес содержит короткое уникальное название товара.

**Как понять, что готово:** если открыть два разных товара, у них будут разные названия, фото, цены и характеристики. Не нужно вручную создавать отдельный файл для каждой модели: одна шаблонная страница показывает данные выбранного товара.

## Шаг 7. Добавь сравнение и избранное
**Сравнение** — это список товаров рядом, чтобы было проще увидеть отличия, например объём памяти и размер экрана.

**Избранное** — список товаров, которые пользователь хочет сохранить на потом.

Для посетителя без аккаунта эти списки можно временно хранить в браузере. После входа избранное нужно сохранить в базе, чтобы оно было доступно при следующем посещении.

**Как понять, что готово:** можно добавить товар, увидеть его в соответствующем списке и удалить оттуда.

## Шаг 8. Сделай корзину
**Что делаем:** создаём отдельную страницу `/cart`.

На ней пользователь сможет:
- добавлять товары;
- увеличивать и уменьшать количество;
- удалять отдельные позиции;
- видеть сумму по каждой позиции и общую сумму.

**Простыми словами:** корзина — список покупок перед кассой.

**Важное правило:** браузеру нельзя доверять окончательную цену. Перед созданием заказа сайт должен заново проверить цену и остатки на сервере по базе данных.

**Как понять, что готово:** после изменения количества сумма меняется правильно, а после обновления страницы корзина не исчезает.

## Шаг 9. Добавь регистрацию и Google
**Что делаем:** пользователь сможет создать аккаунт по email и паролю или войти через Google.

**Простыми словами:** аккаунт позволяет сайту узнать, кто оформляет заказ, и сохранить его избранное и историю покупок.

Нужно настроить разрешённые адреса сайта в настройках Google. Секретный ключ Google хранится только в `.env.local` и в настройках хостинга.

**Как понять, что готово:** можно зарегистрироваться, выйти, войти снова и авторизоваться через Google. Страницы личного кабинета не открываются посторонним.

## Шаг 10. Оформи заказ
**Что делаем:** добавляем форму с именем, телефоном и адресом доставки, а затем создаём заказ.

**Простыми словами:** это оформление покупки перед кассой. Сервер проверяет, что товар ещё есть и цена не изменилась.

Сохраняй в заказе название и цену товара на момент покупки. Тогда история заказа останется понятной, даже если цена в каталоге изменится позже.

**Как понять, что готово:** после подтверждения появляется номер заказа и заказ виден в базе.

## Шаг 11. Подключи тестовую оплату YooMoney
**Что делаем:** подключаем именно тестовый сценарий, который доступен для выбранного продукта YooMoney.

**Простыми словами:** это учебная касса, которая позволяет проверить путь оплаты, не выдавая тестовую операцию за реальную покупку.

1. Сначала проверь официальную документацию и доступность тестового режима.
2. Создавай платёж только на сервере.
3. Секретные ключи держи в переменных окружения.
4. Обрабатывай три результата: успешно, отменено и ошибка.
5. Подтверждай статус оплаты через предусмотренный провайдером серверный механизм. Возврат на страницу «Успех» сам по себе не доказывает, что платёж прошёл.
6. На сайте явно подпиши, что оплата тестовая.

**Как понять, что готово:** все тестовые исходы правильно меняют статус заказа, а повторное уведомление не создаёт второй заказ.

## Шаг 12. Проверь сайт перед показом
Пройди по списку:
- Открываются главная, каталог и страницы товаров.
- Поиск, фильтры и сортировка работают.
- Сравнение и избранное позволяют добавлять и удалять товары.
- Корзина правильно считает сумму.
- Нельзя заказать больше товара, чем есть в наличии.
- Нельзя открыть чужие заказы без разрешения.
- Тестовая оплата показывает успех, отмену и ошибку.
- На телефоне всё читается и не появляется горизонтальная прокрутка.
- Секреты не попали в GitHub.

## Как работать с ИИ-помощником по коду
Не проси создать весь магазин одним огромным запросом. Двигайся по этапам из `TASK.md`.

После каждого этапа пиши:
«Сделай только текущий этап. Сначала проверь существующие файлы, не ломай уже работающие функции, внеси изменения, запусти доступные проверки и объясни простыми словами, что изменилось и как мне это проверить. Если возникла ошибка, исправь её до перехода дальше».

Если помощник предлагает команду, которую нужно вводить в терминал, попроси объяснить:
1. где открыть терминал;
2. какую команду скопировать;
3. что должно появиться после выполнения;
4. что делать, если результат отличается.

## Словарь простыми словами
- **Frontend** — то, что человек видит на сайте.
- **Backend** — невидимая часть, которая проверяет данные и выполняет действия.
- **База данных** — место, где сайт хранит товары, пользователей и заказы.
- **API** — способ, которым части сайта обмениваются данными.
- **Компонент** — повторно используемый кусок интерфейса, например карточка товара.
- **Динамическая страница** — одна заготовка страницы, которая подставляет данные разных товаров.
- **Переменная окружения** — настройка или секрет, который хранится отдельно от исходного кода.
- **Миграция** — контролируемое изменение структуры базы данных.
- **OAuth** — способ войти на сайт через другой сервис, например Google.
- **Webhook/callback** — сообщение от платёжного сервиса о результате операции.
- **MVP** — первая рабочая версия с самыми нужными функциями.

## Что должно получиться в конце
Рабочий демонстрационный магазин техники для Ташкента: каталог из Neon, отдельные страницы товаров, сортировка и фильтры, сравнение, избранное, корзина, регистрация и Google-вход, создание заказа и тестовая оплата. Реальные цены, наличие, доставка и приём денег включаются только после отдельной проверки и настройки.
